# OpenRemote Studio — audit fonctionnel V31.8 / plan de qualification Windows
Auteur : Abdelhalim Talbi. Statut : développement, qualification CI requise pour chaque nouveau commit.

## Objectif produit
Client Windows installable et portable, orienté exploitation infrastructure, avec SSH interactif, SFTP fiable, lancement RDP, VNC via dépendance déclarée, gestion des profils, diagnostics et sécurité des accès.

## Priorité P0 : parcours utilisateurs réels
| Parcours | Composants observés | Critère de recette à confirmer |
| --- | --- | --- |
| Créer un profil et se connecter en SSH | profiles, ssh_transport, qt_app | Authentification sur serveur réel, vérification host key, shell interactif, sortie propre |
| Transférer un fichier en SFTP | qt_workers, transfer_safety, transfer_journal | Upload/download, progression, annulation, absence de corruption, permissions, reprise |
| Ouvrir RDP | rdp_sessions, gateways, external_sessions | mstsc lancé, fichier temporaire supprimé, pas de secret stocké |
| Lancer VNC | remote_tools, windows_client_health | Détection explicite de la visionneuse, message utile si absente |
| Distribuer sous Windows | bootstrap-and-build, verify-release, CI | Installation/désinstallation, exécution portable hors dépôt, dépendances embarquées |

## Résultats et preuves
- V31.8 commit 8a61872 : workflows Windows natif #104 et cumulatif #24 PASS ; ZIP cumulatif réellement généré.
- Inspection de l'archive : 691 entrées, sept répertoires, installateur EXE et portable ZIP, archive lisible.
- Exécution locale sous Linux des tests Application/tests/test_transfer*.py du snapshot V31.8 : 36 tests PASS. Ce résultat n'est **pas** un test Windows, réseau réel ou GUI.
- Audit source : le worker SFTP disposait d'un drapeau d'annulation mais l'upload exclusif ne le consultait pas. Correctif apporté à upload_exclusive et qt_workers ; tests de régression ajoutés. Requalification CI post-correctif indispensable.
- Aucun résultat ne justifie actuellement d'affirmer la compatibilité avec tous les serveurs SSH, RDP et VNC, ni une recette visuelle humaine complète.

## Risques prioritaires et décisions
1. P0 — Connexion SSH interactive : tests sur OpenSSH Windows/Linux, clés, password, erreur host key, interruption réseau, reconnexion.
2. P0 — SFTP : upload atomique/exclusif, annulation au milieu du flux, téléchargement avec reprise, contrôles checksum, collision, quota, droits.
3. P0 — Qualité UX : navigation clavier, contrastes, DPI 125/150/200%, focus, erreurs actionnables, latence de démarrage, fermeture des processus.
4. P0 — Distribution : signature Authenticode (si certificat), antivirus/SmartScreen, install/uninstall, portable sur VM Windows vierge sans Python.
5. P1 — RDP/VNC : dépendances explicitement détectées, statut client et chemin exécutable ; ne pas annoncer un moteur VNC intégré sans preuve.
6. P1 — Secrets : Windows Credential Manager ou coffre chiffré, non-persistance des mots de passe, journalisation sans secrets.
7. P1 — Fiabilité : reprise après crash, concurrence des transferts, absence de blocage du thread GUI.

## Protocole de qualification
Pour chaque correction : tests unitaires ciblés, tests intégration avec serveurs de laboratoire, GUI smoke réel, build installateur/portable, audit de dépendances, SHA-256, provenance commit+run, ZIP cumulatif, documentation et captures **réelles** si disponibles. Si une étape manque : état PARTIAL ou FAIL, jamais PASS global.

## Architecture recommandée
Conserver PySide6/Qt et Paramiko à court terme : migration de framework sans défaut démontré augmenterait les risques. Isoler les services SSH/SFTP, les modèles d'état et les adaptateurs externes de l'interface. Les tâches réseau doivent rester hors thread UI. Séparer explicitement simulation, tests de composants et preuves E2E réelles.
