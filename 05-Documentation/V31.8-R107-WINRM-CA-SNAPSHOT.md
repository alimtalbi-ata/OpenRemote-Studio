# OpenRemote Studio V31.8 — R107 : instantané CA privé pour WinRM

Auteur : **Abdelhalim Talbi** — 25 octobre 2026.

## Correction P1 réelle
R106 détectait un changement du PEM avant connexion, mais `pywinrm` relisait ensuite **le chemin d'origine** : une substitution après la dernière vérification restait possible. R107 supprime cette dépendance à l'original pendant la requête. Un snapshot des octets PEM validés, vérifié contre l'empreinte initiale, est créé avec `O_EXCL` dans un répertoire temporaire propre à la requête. `pywinrm` reçoit uniquement le chemin du snapshot ; le répertoire est supprimé à la fin de `run_ps` ou après une exception.

L'application demeure **hors ligne par défaut**, HTTPS strict, commandes CIM fixes, consentement Qt et identifiants à durée de vie limitée. Le certificat CA est public ; aucun secret n'est écrit. Les exceptions transport sont expurgées. Les tests vérifient que la modification de l'original pendant l'appel ne modifie pas le snapshot utilisé et que le nettoyage est effectif.

## Fichiers et qualification
- `Application/winrm_readonly.py` : lecture sûre, empreinte, snapshot et requête.
- `Application/winrm_services_readonly.py` : même chemin protégé pour les services.
- `Application/tests/test_winrm_ca_snapshot_r107.py` : tests purs avec fichiers réels, transports injectés, aucun réseau.
- `Application/tests/test_winrm_ca_bundle_r105.py` : contrat adapté au snapshot éphémère.
- `.github/workflows/windows-native.yml` et `.github/workflows/v318-cumulative-verification.yml` : gate R107 ; workflow OpenSSH inchangé fonctionnellement.

Commande : `PYTHONPATH=Application python -m unittest discover -s Application/tests -p 'test_winrm_ca_snapshot_r107.py' -v`

**Preuves attendues, non présumées :** tests R107, régressions R105/R106, OpenSSH réel, CI Windows native et cumulative, binaires réellement produits et SHA-256 au commit exact. Ne pas présenter un runner comme recette humaine Windows Server.

## Menaces résiduelles
Un autre processus **sous le même compte utilisateur** pourrait théoriquement modifier un snapshot temporaire s'il acquiert ses droits : la confidentialité/intégrité vis-à-vis de ce même compte ne sont pas garanties. Sur Windows, `0o600` n'est pas une politique ACL complète : revue du DACL effectif et validation sur Windows Server restent requises. Le fichier d'origine est toujours lu pour initialiser la confiance, mais n'est plus relu par `pywinrm` pendant la requête. Aucun test réel WinRM HTTPS, NTLM/Kerberos, PKI entreprise ou interaction humaine n'est revendiqué.
