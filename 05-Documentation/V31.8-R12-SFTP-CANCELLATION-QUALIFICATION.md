# OpenRemote Studio V31.8-R12 — Annulation SFTP typée
Auteur : Abdelhalim Talbi | 21 octobre 2026

## Objectif
Séparer l'annulation volontaire d'un transfert de l'échec réseau ou de l'interruption imposée par une défaillance du journal SQLite. L'état actif n'est libéré qu'après le signal terminal du worker, préservant l'ordre FIFO.

## Contrat
- Worker : signaux exclusifs `finished(object)`, `failed(str)`, `cancelled()`. Seul `InterruptedError` accompagné d'une demande effective d'annulation produit `cancelled`; `OSError` demeure une erreur.
- Queue : `cancel_active` enregistre la demande mais conserve le slot; `complete(...,cancelled=True)` n'accepte pas un résultat réussi.
- UI : callback `on_cancelled` et liaison explicite Qt; aucun parsing de chaînes d'exception.
- Journal : `cancelled` si demande utilisateur confirmée, `failed` si interruption due au contrôle d'audit; échec d'écriture affiché comme audit non confirmé.
- Fermeture d'onglet : annulation coopérative, sans lancement de la tâche suivante sur un onglet fermé.

## Architecture
Utilisateur -> Qt SFTP onglet -> TransferQueue -> SftpJob (thread) -> transport SFTP
                                  |                | finished/failed/cancelled
                                  +-> SQLite journal <- callback Qt
                                  +-> mise à jour liste et état

## Tests automatisés

Tests unitaires de file et worker simulé; tests statiques du raccordement Qt. Aucun serveur distant requis. Les tests ne qualifient ni Windows, ni le protocole SFTP réel.
