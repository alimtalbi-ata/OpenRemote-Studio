# OpenRemote Studio V31.8 — R76 : révocation asynchrone NetBox

**Auteur : Abdelhalim Talbi** · **24 octobre 2026** · **Évolution P1 de sécurité et de fiabilité — qualification de production non revendiquée**

## Problème fonctionnel

R74/R75 permettaient une lecture HTTPS GET opt-in suivie d'une comparaison en mémoire, mais un GET lancé avant le retrait du consentement pouvait terminer et afficher des données après révocation. De même, une réponse tardive de l'origine A pouvait écraser un résultat plus récent de l'origine B. Une fermeture d'onglet pouvait laisser un worker terminer sans invalidation explicite.

**Invariant R76 : aucune réponse d'une requête antérieure ne doit réactiver l'UI, afficher des hôtes ni effacer le résultat d'une requête ultérieure après retrait du consentement, changement d'origine, masquage ou fermeture.**

## Architecture et cinématique

1. Le panneau reste **hors ligne par défaut**. Aucun GET n'est émis sans activation explicite de la case de consentement et action « Comparer maintenant ».
2. Chaque lancement crée une **génération monotone** et un worker `_Fetch` muni d'un `threading.Event` d'annulation. Le worker ne publie que des données d'inventaire limitées et des codes d'erreur stables.
3. Modifier l'origine HTTPS ou le consentement invalide immédiatement la génération, vide le tableau et le cache de comparaison, réactive le bouton et signale le nouvel état. Masquer l'onglet annule la requête active; fermer le panneau interdit de nouveaux lancements.
4. Le résultat du worker est transmis avec son numéro de génération. Le slot Qt refuse toute génération obsolète et toute réponse lorsque le consentement est désactivé ou le panneau fermé. **Un résultat tardif ne peut pas vider un résultat plus récent.**
5. Le client `NetBoxReadOnly.devices(online=True, cancelled=...)` teste le signal d'annulation avant le premier GET, avant chaque page suivante et après la lecture d'une réponse. En cas de révocation, il renvoie le code `netbox_request_cancelled` sans résultat partiel ni nouvelle page.
6. Les adaptateurs de test conservant la signature `devices(online=True)` sont compatibles. La voie de production est le client NetBox GET-only existant; aucun moteur spécialisé n'est dupliqué.

### Schéma de flux

```text
Opérateur (consentement + clic) → génération N → worker Qt → NetBox GET HTTPS
                 │                    │                  │
                 └── révocation ──────┴── Event cancel ──┘
                       │                   │
             cache/table vidés       arrêt entre pages
                       │                   │
               génération N+1 ← réponse N tardive
                       └── réponse N rejetée (aucun rendu)
```

## Menaces et contrôles

| Risque | Contrôle R76 | Limite |
|---|---|---|
| Réponse tardive après révocation | Numéro de génération et vérification consentement au rendu | Ne retire pas les données déjà reçues par un serveur externe |
| Modification de l'origine pendant un GET | Invalidation immédiate; résultat de l'ancienne origine ignoré | Le GET déjà émis peut encore aboutir côté serveur |
| Pagination après révocation | Callback d'annulation vérifié avant et après chaque page | Une lecture réseau déjà bloquée ne peut pas être interrompue de façon garantie |
| Fermeture ou masquage de l'onglet | Invalidation du worker actif et effacement des lignes | Le worker peut rester actif jusqu'au timeout de transport |
| Fuite d'identifiants | Jeton jamais affiché; effacement du champ token worker en `finally`; erreurs réseau génériques | Secret en mémoire pendant la requête; le stockage du processus est hors périmètre |
| Modification NetBox ou catalogue local | GET-only, aucune synchronisation ou import | Les métadonnées de noms d'hôtes sont visibles dans l'UI |

Le timeout HTTP du client de production reste borné (5 secondes par défaut, 30 secondes maximum configurables), avec un nombre de pages borné. Il ne s'agit **pas** d'une annulation TCP immédiate ni d'une garantie de destruction du secret en mémoire.

## Qualification reproductible

Depuis la racine du dépôt :

```powershell
$env:PYTHONPATH = 'Application'
python -m unittest discover -s Application/tests -p 'test_netbox_cancel_r76.py' -v
python -m unittest discover -s Application/tests -p 'test_netbox_cancel_qt_r76.py' -v
python -m unittest discover -s Application/tests -p 'test_netbox_readonly_r73.py' -v
python -m py_compile Application/netbox_readonly.py Application/netbox_preview_qt.py
```

Scénarios nouveaux : hors ligne sans callback ni transport; annulation avant le premier GET; callback invalide; révocation après première page; révocation avant page suivante; pagination normale; worker annulé avant création du client; retrait du consentement pendant un faux GET bloqué; changement d'origine avec deux réponses concurrentes; fermeture pendant un faux GET.

**Frontières de preuve :** six tests unitaires purs exécutés localement sur Linux/POSIX avec transport simulé; quatre tests Qt ajoutés mais ignorés localement faute de PySide6. Les workflows Windows native/cumulative exécutent les tests purs et la suite native peut exécuter les tests Qt. Leur succès et la construction d'installateurs doivent être vérifiés sur les exécutions associées au SHA de la PR. Pas de serveur NetBox réel, pas de capture réelle, pas de validation opérateur Windows indépendante ni de qualification OpenSSH réelle dans R76.

## Critères d'acceptation

- Un clic hors ligne n'effectue aucun GET.
- Retirer le consentement ou changer l'origine efface immédiatement le tableau et rend la réponse précédente inopérante.
- Une requête nouvelle reste visible même si l'ancienne finit plus tard.
- Le client réel ne démarre aucune nouvelle page après annulation détectée.
- Une erreur de transport ne publie ni token ni détail de transport.
- Les tests R73/R74/R75 restent verts et les deux CI Windows réussissent sur le **HEAD exact**.
- Aucun merge de `main`, aucune migration ni écriture NetBox.
