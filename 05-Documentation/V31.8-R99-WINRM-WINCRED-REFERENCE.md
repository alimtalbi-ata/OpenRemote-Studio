# OpenRemote Studio V31.8 — R99 WinCred pour WinRM (25 octobre 2026)

Auteur : **Abdelhalim Talbi**. Branche : `feature/v31.8-r99-winrm-wincred-reference`. PR draft, sans fusion automatique de `main`.

## Problème réel et objectif P1

Les panneaux WinRM R98 exigeaient un mot de passe saisi pour chaque requête ou un fournisseur injecté au constructeur. La fenêtre principale ne proposait aucune sélection de référence de coffre. R99 ajoute une référence **locale** à un Generic Credential Windows déjà provisionné, sans réimplémenter Vault ni exiger une connexion réseau vers un gestionnaire de secrets.

## Architecture et flux de sécurité

```text
Opérateur (Qt WinRM OS/disques ou services)
  -> saisie HTTPS + compte + wincred:<target> (pas de secret)
  -> validation locale des paramètres + référence
  -> consentement explicite (révoqué si champ modifié)
  -> worker QRunnable unique (génération, annulation)
  -> Windows Credential Manager / CredReadW (secret en mémoire)
  -> WinRMReadOnly / WinRMServicesReadOnly
  -> pywinrm optionnel / HTTPS avec vérification TLS
  -> requête PowerShell CIM fixe, lecture seule
  -> normalisation et tableau Qt (aucun secret)
```

L'absence de référence conserve le prompt masqué éphémère existant. Aucun secret n'est sauvegardé dans les profils, journaux ou exports par ce nouveau parcours. Les références sont limitées à `wincred:` suivi d'un identifiant ASCII borné ; `..`, caractères de contrôle, espaces, URL, schémas tiers et séquences ambiguës sont rejetés. Aucun repli silencieux vers un mot de passe en clair après échec WinCred.

## Comportements et cas de tests

| Cas | Résultat attendu | Preuve |
|---|---|---|
| Hors ligne | Aucune résolution de secret, aucun réseau | Test Qt R99 synthétique |
| Référence invalide | Refus avant CredReadW et WinRM | Tests purs + Qt R99 |
| Référence valide | Résolution dans worker, jamais dans thread UI | Test Qt R99 synthétique |
| Révocation | Modifier origine/compte/référence décoche le consentement et invalide les résultats | Test Qt R99 synthétique |
| Erreur du coffre | Code fermé, exception sensible non affichée | Tests purs + Qt R99 |
| Mot de passe absent | Pas de connexion ni repli implicite | Tests purs R99 |

## Dépendances, limites et non-preuves

- Fonctionne seulement sous Windows avec une entrée **Generic Credential** accessible au compte exécutant OpenRemote Studio. Le logiciel **ne crée pas** cette entrée.
- `pywinrm` reste optionnel ; aucune qualification réseau Windows Server ni NTLM/Kerberos de production n'est revendiquée.
- Les tests Qt emploient un transport simulé et un résolveur injecté ; **aucune preuve de lecture CredReadW réelle** n'est revendiquée.
- Aucune capture R99 de l'interface ni recette opérateur sur poste Windows physique disponible au moment de la rédaction.
- Les tests CI et les artefacts sont à vérifier au commit exact avant d'affirmer une release Windows R99.
