# OpenRemote Studio V31.8 — R102 : réponses WinRM strictes et bornées

**Auteur : Abdelhalim Talbi** · **Priorité : P1 sécurité et fiabilité** · **État : en qualification CI**

## Défaut confirmé dans le code R101
Les deux adaptateurs `winrm_readonly.py` et `winrm_services_readonly.py` décodaient indépendamment les réponses `run_ps`. Le décodeur JSON standard acceptait les clés dupliquées (dernière valeur gagnante) et les nombres non finis ; les propriétés `status_code` / `std_out` d'un objet transport inattendu pouvaient lever des exceptions non expurgées.

## Correction fonctionnelle R102
Le module `Application/winrm_response.py` centralise les contrôles pour l'inventaire OS/disques et les services : statut entier strict égal à zéro, réponse `bytes` de 1 à 65 536 octets, JSON UTF-8 strict sans clé dupliquée ni NaN/Infinity, profondeur excessive refusée. Les erreurs de lecture des propriétés du transport sont remplacées par `winrm_invalid_response`, sans exposer les exceptions ou `std_err`. Les statuts distants non nuls deviennent `winrm_remote_query_failed`.

Aucun changement du modèle de consentement, des requêtes CIM constantes, de la validation TLS HTTPS, des références WinCred ni de l'absence de connexion hors ligne.

## Tests et preuves
`Application/tests/test_winrm_response_r102.py` : 6 tests avec doubles de transport, couvrant les deux backends, réponses valides, clés dupliquées, NaN/Infinity, taille, profondeur, mauvais types, exceptions contenant un secret, statut distant et absence d'appel réseau hors ligne. Régressions R93 et R95 : 7 + 7 tests. **Résultats locaux Linux : 20/20 PASS** ; les CI Windows, OpenSSH et ZIP R102 doivent être constatés au SHA final avant attestation.

## Limites et acceptation
Ces tests n'établissent pas une connexion WinRM HTTPS à un véritable Windows Server, une chaîne de confiance CA, NTLM/Kerberos réels, ni une recette opérateur Windows physique. Aucun nouveau screenshot réel R102 n'est disponible ; ne pas confondre diagramme conceptuel et capture. État Windows Admin Center : **PARTIAL**. Couverture globale : 7 PARTIAL, 5 NOT_IMPLEMENTED, 0 IMPLEMENTED. Aucune fusion automatique de `main`.
