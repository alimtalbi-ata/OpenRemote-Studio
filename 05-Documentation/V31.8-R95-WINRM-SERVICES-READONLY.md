# OpenRemote Studio V31.8 — R95 : inventaire des services Windows en lecture seule

**Auteur : Abdelhalim Talbi — 24 octobre 2026.**

## Fonctionnalité
`Application/winrm_services_readonly.py` fournit `WinRMServicesReadOnly.services(online=True)`, un inventaire borné des services Windows via le transport HTTPS WinRM existant. Le script PowerShell est constant : `Get-CimInstance Win32_Service`, tri alphabétique et sélection des 128 premiers services. Aucun nom de service fourni par l'utilisateur n'est interpolé, aucune action `Start-Service` ou `Stop-Service` n'est exposée.

Le résultat ne contient que le nom, le libellé, l'état et le mode de démarrage. Il annonce `may_be_truncated=True` lorsque 128 entrées sont retournées ; **ne pas présenter cette liste comme exhaustive**. Les réponses JSON de plus de 64 KiB, les noms dupliqués, les caractères de contrôle, les états inconnus et les formes incorrectes sont rejetés.

## Sécurité et fonctionnement
Hors ligne par défaut ; aucun appel au fournisseur d'identifiants ou au réseau sans `online=True`. Origine HTTPS, validation du certificat, fournisseur de mot de passe à l'exécution, timeout WinRM borné et exceptions expurgées hérités de `WinRMReadOnly`. Une annulation avant la requête ou après la réponse est respectée, mais un POST déjà lancé n'est pas interrompu immédiatement. Aucun secret n'est persisté, exporté ou affiché ; Python ne garantit pas l'effacement cryptographique des chaînes en mémoire.

## API Python
```python
from winrm_services_readonly import WinRMServicesReadOnly

client = WinRMServicesReadOnly(
    'https://windows.example.internal:5986', 'read-only-user',
    credential_provider=get_temporary_password)
# Aucun accès réseau jusqu'à cet appel explicite :
result = client.services(online=True)
```
Exemple de code uniquement : **aucune connexion réelle à Windows Server n'a été effectuée pour R95**.

## Tests et preuves
`Application/tests/test_winrm_services_r95.py` contient sept tests contractuels : offline, script fixe et projection, annulation, validation stricte, expurgation d'exception, refus des credentials invalides, sortie vide et objet unique. Exécutés localement avec `Application/tests/test_winrm_readonly_r93.py` issu du ZIP R93 : **14/14 PASS** en environnement POSIX avec faux transport. Cette preuve ne qualifie ni `pywinrm` réel, ni le panneau Qt, ni le packaging Windows R95.

## Limites et suite
Le panneau Qt R94 n'expose pas encore cet inventaire de services. Le backend reste **PARTIAL**, avec Windows Server réel **UNVERIFIED**. Ajouter une vue Qt avec consentement distinct, gestion de la troncature et recettes HTTPS WinRM sur serveur jetable à privilèges minimaux. Ne jamais annoncer CI Windows ou ZIP R95 avant inspection des artefacts au SHA exact.
