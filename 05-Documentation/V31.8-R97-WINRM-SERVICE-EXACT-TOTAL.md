# OpenRemote Studio V31.8 — R97 : dénombrement fiable des services WinRM

Auteur : **Abdelhalim Talbi**. Date : 24 octobre 2026. PR draft empilée sur R96 ; aucune fusion automatique.

## Défaut corrigé (P1, exactitude opérateur)
R96 indiquait « potentiellement tronqué » dès que 128 services étaient retournés. Un hôte ayant **exactement 128 services** ne pouvait pas être distingué d'un hôte en ayant davantage. Cela pouvait induire une interprétation erronée de l'inventaire.

## Fonctionnement R97
La requête PowerShell fixe et **lecture seule** récupère une fois les services via `Get-CimInstance Win32_Service`, puis renvoie dans le même document JSON `TotalCount` et les 128 premières lignes triées. Aucun script fourni par l'utilisateur, aucune commande de démarrage/arrêt de service, aucune seconde requête réseau. L'interface affiche `128/128` (complet) ou `128/129` (tronqué), et refuse un compteur incohérent avant rendu.

Le parseur `Application/winrm_service_totals.py` impose un compteur entier strict, 0–1 000 000, et exactement `min(total,128)` lignes. Les anciens jeux de données sans compteur restent compatibles : total inconnu, avertissement prudent. Aucun champ de secret, de token ou de mot de passe n'est accepté dans l'enveloppe. Les erreurs restent codées `winrm_invalid_response` sans recopier les valeurs distantes.
