# OpenRemote Studio V31.8 — R105 : CA interne WinRM HTTPS

**Auteur : Abdelhalim Talbi — 25 octobre 2026.**

## Fonction P1
Les deux panneaux Qt Windows (OS/disques et services) acceptent un fichier PEM CA facultatif. Vide : magasin de confiance système, inchangé. Renseigné : fichier local absolu explicitement approuvé par l'opérateur, transmis à `pywinrm.Session(ca_trust_path=...)` avec `server_cert_validation='validate'`. Aucune option HTTP ni bypass TLS.

La validation précède la lecture du mot de passe : rejet des chemins relatifs, partages UNC, symlinks, fichiers non réguliers, vides, >1 Mio et PEM non analysables par la bibliothèque TLS. Les erreurs sont des codes fixes sans chemin ni secret. Modifier la CA révoque le consentement Qt et les réponses asynchrones périmées.

## Tests et captures
- 8 tests backend `test_winrm_ca_bundle_r105.py` : véritable certificat PEM public, erreurs, symlink, aucun accès secret en cas de refus, inventaire et services, contrat pywinrm.
- 3 tests Qt `test_winrm_ca_bundle_qt_r105.py` : révocation, refus avant secret, propagation au worker. Exécution attendue sous Windows CI PySide6.
- `fixtures/r105-public-test-ca.pem` : certificat de laboratoire **public uniquement**, aucune clé privée, ne pas l'utiliser en production.
- `capture_winrm_ca_qt_r105.py` : capture d'une vraie interface Qt **hors ligne** si la CI réussit. Pas une preuve de connexion Windows Server.
- Régressions R93–R104, OpenSSH réel et construction Windows maintenues dans les workflows.

## Limites
WinRM HTTPS sur un véritable Windows Server, certificat d'entreprise, chaîne CA et nom DNS, NTLM/Kerberos, compte à privilèges minimaux, annulation et timeout **UNVERIFIED**. Recette future : WinCred → consentement Qt → CA interne → WinRM HTTPS → CIM, plus refus de mauvaise CA, mauvais DNS, certificat expiré et mauvais mot de passe. Aucune fusion automatique de `main`.
