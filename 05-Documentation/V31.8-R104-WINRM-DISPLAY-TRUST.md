# OpenRemote Studio V31.8 — R104 : frontière de confiance de l'affichage WinRM

**Auteur : Abdelhalim Talbi** · **25 octobre 2026** · P1 sécurité · PR draft empilée sur R103.

## Défaut concret corrigé

Les champs texte de réponse CIM étaient vérifiés contre les contrôles ASCII mais acceptaient encore des caractères Unicode invisibles (direction droite-gauche, isolats bidirectionnels, espace zéro largeur, C1, séparateurs Unicode, substituts non appariés et non-caractères). Ces caractères peuvent rendre trompeurs les noms de services ou d'ordinateurs dans un tableau Qt. De plus, la branche UI inventaire OS/disques acceptait sans revalidation certaines réponses de clients injectés, malgré la normalisation du backend standard.

## Implémentation

- `Application/winrm_readonly.py` : `_text()` rejette les catégories Unicode Cc/Cf/Cs/Zl/Zp et les non-caractères Unicode, tout en conservant les caractères internationaux visibles (accents, japonais, etc.).
- `Application/winrm_inventory_qt.py` : les services reçus sont revalidés par `_text()`, même depuis un client injecté. Les réponses OS/disques sont revalidées avant toute insertion dans `QTreeWidget` : `read_only=True`, liste bornée, champs texte, lettres de lecteur uniques, tailles entières et espace libre <= taille.
- Les refus produisent le message neutre « Réponse WinRM invalide. », sans reprendre le contenu distant.
- Aucun changement aux scripts CIM fixes, aux appels réseau, à l'authentification, à la validation TLS ni au consentement explicite.
