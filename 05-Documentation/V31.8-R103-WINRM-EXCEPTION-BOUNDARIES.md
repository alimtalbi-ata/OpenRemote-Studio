# OpenRemote Studio V31.8 — R103 : frontières d'erreurs WinRM

**Auteur : Abdelhalim Talbi — 25 octobre 2026.** P1 sécurité ; aucune recette WinRM distante réelle revendiquée.

## Défaut R102 et correction
Les backends `WinRMReadOnly.inventory` et `WinRMServicesReadOnly.services` propageaient une `WinRMError` émise par un transport externe. Le décodeur partageait ce défaut pour les accesseurs `status_code` et `std_out`. Une erreur d'adaptateur pouvait donc contenir du stderr distant ou un secret. Le worker Qt plaçait également un code non reconnu dans le signal `finished`.

R103 transforme **toute** exception de session ou `run_ps` en `winrm_transport_unavailable`, et les exceptions des propriétés de réponse en `winrm_invalid_response`, sans chaînage visible. Un statut distant non nul retourne `winrm_remote_query_failed` sans lire le corps. Le signal Qt accepte uniquement une liste blanche de codes fixes. Aucune requête PowerShell libre ni écriture distante n'est introduite.

## Qualification
`PYTHONPATH=Application python -m unittest discover -s Application/tests -p 'test_winrm_exception_boundary*r103.py' -v`. Scénarios : erreurs `RuntimeError` et `WinRMError` hostiles, construction de session, `run_ps`, propriétés de réponse, statut distant non nul, hors ligne sans réseau, signal Qt sans secret. Régressions R93/R95/R102. Les tests backend utilisent des transports simulés; le test Qt nécessite PySide6 et la CI Windows. Les résultats CI et le ZIP ne doivent être attestés qu'au SHA exact.
