# OpenRemote Studio V31.8 — R101 : runtime WinRM embarqué et qualifié hors ligne

**25 octobre 2026 — Auteur : Abdelhalim Talbi.** Branche `feature/v31.8-r101-winrm-packaged-runtime`, PR draft empilée sur R100 ; `main` non modifiée.

## Audit G0 et choix P1

MobaXterm, Royal TS, Devolutions RDM, mRemoteNG, Termius, Windows Admin Center et NetBox : **PARTIAL**. Ansible, Zabbix, Grafana, Wireshark et HashiCorp Vault : **NOT_IMPLEMENTED**. Aucun IMPLEMENTED. Windows Admin Center restait PARTIAL : backend WinRM R93–R100 et UI Qt, mais la dépendance `pywinrm` était absente de `Application/requirements.txt` et les specs PyInstaller ne collectaient pas `winrm`. Le build pouvait produire un exécutable qui répond `winrm_dependency_missing` à la première requête en ligne.

## Correction fonctionnelle

1. La dépendance `pywinrm>=0.5,<0.6` est intégrée à la compilation Windows, avec collecte explicite des sous-modules `winrm` et `spnego`. Les dépendances transitives NTLM et requests sont vérifiées. Aucun composant serveur n'est installé.
2. Les deux specs préservent le contrat R70 : PyInstaller fournit `SPECPATH` comme **répertoire du fichier spec**, donc `Path(SPECPATH).resolve().parent` désigne `Application`. Les chemins `root / 'qt_app.py'` et `root.parent / 'VERSION.txt'` sont corrects ; le nouveau contrôle évite toute régression de cette résolution.
3. Le programme accepte `--check-winrm-runtime` : exit 0 lorsque les modules essentiels sont disponibles, exit 13 sinon, **sans accès réseau, lecture de coffre ni démarrage du GUI**. Aucun détail de bibliothèque ni secret n'est imprimé.
4. `Application/windows/winrm-runtime-smoke.ps1` exécute ce contrôle avec timeout et arrêt du processus. Le build refuse la publication tant que le **binaire PyInstaller** et le **portable extrait** n'ont pas réussi.

## Contrats QA et vérification

`Application/tests/test_winrm_runtime_r101.py` teste les modules absents, le graphe complet synthétique, les symboles manquants et le câblage des deux modes de packaging. `test_packaging_spec_paths_r70.py` vérifie les chemins corrigés. Ces tests de contrat **ne remplacent pas** le contrôle exécutable Windows. Les CI native/cumulative exécutent les tests R101 et le build réel avec les deux smokes. OpenSSH conserve sa recette réseau réelle indépendante.

## Exécution / sécurité

Le contrôle du runtime est un diagnostic **offline** et n'exécute aucune commande PowerShell. L'utilisation de WinRM reste soumise à consentement Qt explicite, HTTPS avec validation TLS, compte WinCred fourni à l'exécution, requêtes CIM constantes en lecture seule, erreurs expurgées, aucun secret dans les logs ou exports. Aucune bascule silencieuse en HTTP.

## Limites et suite

**WinRM HTTPS réel non qualifié** : aucun serveur Windows Server isolé, CA de laboratoire, compte lecture seule, ni validation NTLM/Kerberos de bout en bout. La recette opérateur Windows physique et la compatibilité des configurations d'entreprise restent UNVERIFIED. Ne pas présenter les captures Qt hors ligne comme des preuves de session WinRM. Les binaires et le ZIP R101 ne doivent être annoncés qu'après réussite de la CI et vérification SHA-256 sur le commit final.

**Prochain P1 :** déployer une cible Windows Server de test explicitement autorisée et qualifier le parcours Credential Manager → Qt → WinRM HTTPS → CIM, avec refus certificat, identifiants absents et timeout, sans secrets dans les artefacts.
