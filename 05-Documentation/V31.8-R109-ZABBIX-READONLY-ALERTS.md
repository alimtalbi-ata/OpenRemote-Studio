# OpenRemote Studio V31.8 — R109 : triage Zabbix en lecture seule

Auteur : **Abdelhalim Talbi**. Statut : code et tests ajoutés sur branche dédiée ; la qualification définitive dépend des workflows CI attachés au commit exact.

## Cas d'usage livré

Le menu **Outils → Alertes Zabbix (lecture seule)** ouvre un panneau Qt asynchrone qui consulte les problèmes actifs dans une instance Zabbix autorisée. Il affiche la sévérité, l'état acquitté/non acquitté, l'heure du dernier changement en UTC, les hôtes retournés par les triggers et les profils locaux candidats correspondants. Le rapprochement local est indicatif : aucune session SSH/RDP/SFTP n'est ouverte automatiquement.

Le backend **Application/zabbix_readonly.py** n'expose que deux méthodes JSON-RPC de lecture : **problem.get** et **trigger.get**. Il ne fournit aucun code d'acquittement, de modification de problème, de changement de trigger ou de configuration d'hôte.

## Sécurité et comportement

- Mode hors ligne par défaut. L'ouverture du panneau, les changements de formulaire et les filtres locaux n'envoient aucune requête et ne lisent aucun jeton.
- L'accès réseau exige la case de consentement, une origine HTTPS valide, puis OPENREMOTE_ZABBIX_TOKEN transmis dans l'en-tête Authorization: Bearer. Le jeton n'est ni placé dans les paramètres JSON-RPC, ni persisté, ni montré dans l'interface ou une erreur.
- TLS conserve la validation standard du système/Python. Les redirections HTTP sont refusées. Timeout borné, réponse limitée à 1 Mio, liste limitée à 100 problèmes et structures JSON/de profondeur bornées.
- Les réponses refusent les propriétés JSON dupliquées, NaN/Infinity, les identifiants du mauvais type, les plages numériques incohérentes et les caractères Unicode invisibles/bidirectionnels dans les libellés.
- Les erreurs réseau, HTTP, authentification et API sont traduites en codes neutres. Le corps d'erreur distant et les exceptions brutes ne sont jamais repris dans le statut Qt.
- Les filtres de sévérité et de recherche opèrent uniquement sur le dernier instantané en mémoire. Ils ne relancent pas l'API.
- Le worker est asynchrone et coopérativement annulable. Une lecture HTTPS déjà en attente reste limitée par son timeout ; les résultats devenus obsolètes après retrait du consentement ou modification de l'origine ne sont pas affichés.
- Le rapprochement local lit uniquement les champs name, protocol et host des profils ; les champs de credentials ne sont pas consultés. Les candidats sont présentés comme des indices pour revue humaine.

## Configuration opérateur

Créer dans Zabbix un compte/service token dédié limité aux méthodes de consultation nécessaires, idéalement avec accès en lecture seule aux hôtes et événements concernés. Sur le poste opérateur, définir le jeton dans l'environnement du processus avant de lancer OpenRemote Studio :

PowerShell, dans la session opérateur :
    
    $env:OPENREMOTE_ZABBIX_TOKEN = '<jeton fourni par le coffre local>'

Saisir dans le panneau l'origine HTTPS de Zabbix, par exemple https://zabbix.example.internal/zabbix, puis cocher explicitement l'autorisation réseau et lancer la lecture. Après usage, fermer l'application et supprimer la variable de l'environnement du processus. Ne jamais committer de jeton ou le placer dans l'historique de commande, l'URL, les arguments, un fichier versionné ou les logs CI.

## Limites et prochaine étape

Le panneau interroge les problèmes actifs limités ; il ne permet pas de confirmer/acquitter un événement ni d'exécuter une réparation. Aucun accès API réel n'est qualifié dans ce cycle. La prochaine étape sera une recette facultative contre un Zabbix de laboratoire, avec un jeton à privilèges minimaux, tests TLS/permissions/rate-limit et vérification des champs permis, avant d'envisager un deep-link de contexte sans token dans l'URL.


## Correctif R110 — consentement lié à la cible

Toute édition de l'origine HTTPS décoche maintenant le consentement, efface l'instantané affiché et invalide les résultats en vol. Revoir la cible puis recocher l'autorisation est requis avant une nouvelle lecture ou résolution du jeton. Voir [la note R110](V31.8-R110-ZABBIX-CONSENT-BINDING.md). Une lecture HTTPS déjà engagée reste bornée par son timeout ; ses résultats tardifs sont rejetés. La connexion à une instance réelle Zabbix et le rôle effectif à privilèges minimaux restent UNVERIFIED.
