# OpenRemote Studio V31.8 — R87 : reprise manuelle du tunnel SSH Qt

**Auteur : Abdelhalim Talbi** · 24 octobre 2026

## Problème P1 observé dans le code R86
Après un échec de connexion SSH ou une perte du transport, `SSHTunnelPanel._refresh()` arrêtait son timer et désactivait le bouton de fermeture, mais laissait `Démarrer` désactivé et tous les champs en lecture seule. Le contrôleur est intentionnellement à usage unique. Sans recréer l'onglet, l'opérateur ne pouvait pas corriger la configuration puis retenter la connexion.

## Correction fonctionnelle
Un bouton **Nouvelle tentative** est disponible uniquement lorsque le contrôleur signale `closed`, `failed` ou `disconnected` **après confirmation du nettoyage**. Il recrée un contrôleur neuf, déverrouille les champs et remet le consentement à **non coché**. La connexion ne démarre jamais à l'activation de ce bouton : l'opérateur doit de nouveau cocher son consentement puis appuyer sur **Démarrer**.

Le bouton est interdit tant que le nettoyage est en cours ou lorsqu'un callback de fermeture de l'onglet/fenêtre est enregistré. Aucune clé d'hôte n'est acceptée automatiquement, aucune reconnexion silencieuse n'est créée et aucun secret n'entre dans le statut.

## Tests et qualification
`Application/tests/test_tunnel_manual_retry_qt_r87.py` définit quatre scénarios Qt :
1. Échec, nouvelle tentative manuelle, nouveau contrôleur et nouveau consentement.
2. Refus de nouvelle tentative pendant `cleanup`, puis autorisation après `disconnected`.
3. Révocation explicite, puis réinitialisation sans réutiliser l'ancien contrôleur.
4. Fermeture demandée par le parent : aucune reprise possible.

**Preuves à confirmer** : résultats des quatre tests sur Windows, suite complète Windows, CI cumulative, OpenSSH réel, rendu Qt sur poste physique, installateur/portable. L'ajout de tests ne constitue pas leur réussite. Les contrôleurs des tests sont simulés; aucun tunnel réseau réel n'est ouvert par ces tests.

## Sécurité et limites
Le nettoyage des ressources réseau reste délégué au contrôleur R84–R86. Le mécanisme de keepalive R85–R86 n'est pas une preuve de détection bornée des blackholes. La fermeture de l'onglet n'autorise aucune reconnexion, même si une ancienne requête de fermeture est achevée.

## Prochain cycle
Qualifier sur Windows l'enchaînement échec d'authentification → modification du profil → nouvelle autorisation → nouvelle connexion OpenSSH réelle en environnement isolé; puis tester l'interface Qt et les fontes réelles.
