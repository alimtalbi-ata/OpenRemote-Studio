# V31.8 R85 — Keepalive SSH optionnel (architecture et qualification)

Auteur : Abdelhalim Talbi. Statut : développement sur branche, non qualifié Windows.

## Problème
Le watchdog R84 utilise transport.is_active(), qui ne détecte pas forcément une coupure réseau silencieuse. Le keepalive Paramiko aide à détecter un transport non répondant, sans promettre une détection instantanée.

## Modification
TunnelController.start(..., keepalive_seconds=0) accepte un entier strict entre 0 et 300. La valeur 0 conserve le comportement antérieur. Pour une valeur positive, le contrôleur appelle transport.set_keepalive() sur le transport authentifié avant toute ouverture du listener local. Une erreur ferme les ressources et empêche l'activation du tunnel.

## Sécurité
La politique SSH host-key fail-closed reste inchangée. Aucun secret n'est journalisé. Aucune reconnexion automatique. Le keepalive n'est pas un délai maximal garanti : les timeouts TCP, le comportement serveur et les pannes réseau influencent la détection.

## Tests
Trois tests unitaires locaux avec client SSH simulé : validation des bornes, activation avant écoute et échec fermé sur transport sans API. Ils ne démontrent ni une coupure blackhole réelle ni une qualification Windows.

## Suite
Ajouter la configuration du keepalive dans le panneau Qt, puis une recette OpenSSH isolée avec perturbation réseau contrôlée et métriques de temps de détection. Ne pas toucher à la production.
