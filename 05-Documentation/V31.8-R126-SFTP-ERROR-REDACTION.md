# OpenRemote Studio V31.8 — R126 : diagnostics SFTP expurgés

**Auteur : Abdelhalim Talbi.** **Date : 26 octobre 2026.** Branche dédiée : `feature/v31.8-r126-sftp-error-redaction`, empilée sur R125. La PR doit rester en brouillon ; aucune fusion automatique dans `main`.

## Défaut confirmé

`Application/qt_workers.py` transformait les exceptions de `SftpJob` en messages en interpolant `str(exc)`. Les exceptions provenant de Paramiko ou des fonctions de transfert peuvent transporter des détails hors du contrat de diagnostic : chemins locaux ou distants, hôtes, contenus d'erreur de bibliothèques ou valeurs sensibles ajoutées par un adaptateur. Le worker envoyait ce contenu via son signal `failed`, où il pouvait être affiché ou repris par un journal de transfert.

## Correctif R126

- Nouveau module `Application/sftp_error_reporting.py` : transforme les classes courantes (délai, accès refusé, fichier absent, interruption/perte de connexion, paramètres invalides) en messages français constants.
- Le chemin générique ne renvoie qu'un message neutre. Le helper n'appelle ni `str(exc)` ni `repr(exc)`, ne concatène aucun errno arbitraire et tolère une propriété `errno` personnalisée qui lève une exception.
- `SftpJob` utilise le même contrat dans ses chemins d'exception. L'état `cancelled` reste distinct de `failed` et le nettoyage R123–R125 reste inchangé.
- Les tests injectent des chaînes sentinelles assimilables à un secret et des chemins privés dans les exceptions ; ils vérifient que ces valeurs ne franchissent pas le signal Qt.

## Tests et portes CI

- `Application/tests/test_sftp_error_reporting_r126.py` : contrat pur, sans réseau, tests de non-divulgation et de classification.
- `Application/tests/test_sftp_error_redaction_worker_r126.py` : tests d'intégration du worker/Qt avec un faux client SFTP déterministe. Windows natif et cumulatif exigent PySide6 et doivent exécuter ces tests sans skip.
- `.github/workflows/v318-openssh-live.yml` exécute le contrat pur, puis conserve sa recette SFTP/TCP réelle avec un serveur OpenSSH jetable.
- Les workflows Windows natif et cumulatif vérifient le module, les deux suites et l'exécution du worker dans le runtime construit.

Le ZIP cumulatif ne doit être déclaré release que si les trois workflows réussissent au même SHA, si l'installateur/portable sont réellement construits et vérifiés, et si les manifestes SHA-256 réconcilient les sources et l'archive.

## Limites

Cette correction masque les erreurs propagées par `SftpJob`; elle n'affirme pas que toutes les autres fonctions de diagnostic de l'application ont déjà été expurgées. En particulier, les messages de diagnostics TCP et les adaptateurs non-SFTP restent à réauditer dans un cycle séparé. Les messages fixes réduisent la précision des détails bas niveau ; les détails d'exception ne sont volontairement pas exportés ou journalisés par ce chemin. Aucun secret de production, hôte métier ou opération distante n'est utilisé. Le test de worker utilise un transport factice ; la gate OpenSSH distincte qualifie les scénarios de transport, mais pas chaque type d'exception d'un serveur d'entreprise.

Aucun changement UI : aucune capture R126 n'est revendiquée. Auteur et provenance du code : Abdelhalim Talbi.


## Compatibilité des contrats de test

La première exécution R126 a correctement fait échouer une ancienne assertion de R124 qui attendait le préfixe brut `OSError:` dans le signal Qt. Le test conserve sa vérification importante — une panne de transport non sollicitée reste `failed` — mais vérifie désormais le message générique expurgé de R126 et l'absence du texte d'exception. Ce n'est pas une suppression de la couverture de panne : seul le contrat d'exposition du message est renforcé.
