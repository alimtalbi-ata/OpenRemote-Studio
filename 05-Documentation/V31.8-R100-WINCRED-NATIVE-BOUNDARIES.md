# OpenRemote Studio V31.8 — R100 : WinCred natif, bornes mémoire et recette Windows

**25 octobre 2026 — Auteur : Abdelhalim Talbi.** PR draft sur la branche `feature/v31.8-r100-wincred-native-boundaries`, empilée sur R99 ; aucune fusion automatique.

## Constat P1 et correction effective

Le lecteur WinCred R99 utilisait `CredentialBlobSize` directement dans `ctypes.string_at`, sans limite explicite. Une structure native corrompue pouvait demander une lecture excessive. R100 applique `CRED_MAX_CREDENTIAL_BLOB_SIZE=2560` **avant** la copie, vérifie `CRED_TYPE_GENERIC`, refuse tailles nulles/impaires, UTF-16LE invalide et NUL embarqué, et conserve `CredFree` sur les chemins d'échec. Pas de secret dans les logs.

## Recette native réellement automatisée, sans serveur WinRM

`Application/tests/test_windows_credentials_native_r100.py` vérifie six chemins synthétiques (Unicode, type, longueur, NUL, UTF-16 invalide, tailles nulles/impaires) et une recette Windows native : `CredWriteW` d'une entrée **aléatoire, session-only** `OpenRemoteStudio/R100QA/<random>`, lecture par le vrai résolveur `wincred:`, `CredDeleteW` dans `finally`, vérification du refus après suppression. Aucun compte réel ni secret de production n'est utilisé. Sur POSIX, le test natif est explicitement SKIP, pas PASS. La CI Windows doit confirmer son résultat au commit exact.

## Matrice de sécurité

| Scénario | Comportement attendu |
|---|---|
| Type autre que Generic | Refus avant lecture |
| Taille > 2560 ou impaire | Refus avant `string_at` |
| Secret UTF-16 invalide / NUL | Refus, `CredFree` |
| Référence `wincred:` absente | Erreur fermée, aucun fallback |
| Session-only sur runner Windows | `CredWriteW` → `CredReadW` → `CredDeleteW` |
| WinRM hors ligne | Aucun accès réseau |

## Limites et suites

Cette recette locale n'est **pas** une preuve de WinRM HTTPS réel, d'un compte Windows Server en lecture seule, de validation d'une CA de laboratoire, d'un client `pywinrm` embarqué, ni d'un parcours opérateur Windows physique. Aucun snapshot fictif. Prochain cycle : laboratoire WinRM HTTPS isolé et qualification de la dépendance `pywinrm` dans l'installateur Windows.
