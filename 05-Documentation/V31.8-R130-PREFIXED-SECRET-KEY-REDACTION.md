# OpenRemote Studio V31.8 — R130 : expurgation des secrets aux noms préfixés

**Auteur : Abdelhalim Talbi.** Date : 27 octobre 2026. Branche dédiée : `feature/v31.8-r130-env-secret-redaction`.

## Défaut P1 confirmé

R128/R129 protégeaient déjà de nombreuses affectations directes, jetons, URL avec identifiants, cookies/JWT et blocs PEM/PGP. Un trou restait possible quand le nom de variable ajoutait un préfixe fournisseur ou environnement avant le composant sensible : `GITHUB_TOKEN`, `AZURE_CLIENT_SECRET`, `AWS_SESSION_TOKEN`, `AWS_ACCESS_KEY_ID`, `PGPASSWORD`, `NPM_CONFIG__AUTH`, `GOOGLE_APPLICATION_CREDENTIALS` ou `DOCKER_AUTH_CONFIG`. La frontière stricte du filtre de mots-clés simples ne reconnaissait pas nécessairement le suffixe sensible dans ces noms composés.

## Correction

`Application/session_incident_center.py` ajoute un analyseur borné d'affectations de variables :

- normalise le nom pour reconnaître les composants sensibles exacts, les clés API/accès/privées et les identifiants de connexion ;
- couvre `=` et `:`, noms entre guillemets dans un diagnostic JSON, valeurs simples/citées et objets/collections JSON sur une ligne ;
- reconnaît les formes accolées courantes comme `PGPASSWORD` et `MYSQL_PWD`, ainsi que les variables d'authentification terminant par `_AUTH` ;
- remplace la valeur reconnue par `[REDACTED]`, sans appeler `str()` ni `repr()` sur les objets d'adaptateur et sans changer le schéma d'export `openremote.incidents.v1`.

Les tests vérifient aussi que `RETRY_COUNT`, `REQUEST_TIMEOUT`, `DISPLAY_NAME`, `AUTH_MODE`, `TOKENIZER` et `HOST_KEY_TYPE` restent visibles ; le correctif ne redige donc pas tout nom contenant une sous-chaîne ressemblant à un mot secret.

## Qualification ajoutée

`Application/tests/test_incident_export_redaction_r130.py` couvre les préfixes fournisseur courants, les noms accolés, les valeurs citées/JSON, la sensibilité à la casse et les faux positifs non sensibles. Le test et la compilation du module sont ajoutés aux trois gates : Windows natif/runtime construit, OpenSSH/SFTP (tests offline plus recette OpenSSH réelle existante), et cumulative Windows/runtime empaqueté avant assemblage.

Les résultats doivent être consultés au même SHA de tête de PR. Aucun SUCCESS n'est présumé par cette note.

## Documentation / preuve

Le référentiel des douze outils et l'audit G0 R130 sont mis à jour. Le SVG associé est un diagramme conceptuel de la frontière d'expurgation, pas une capture de l'interface. Aucun écran R130 n'est revendiqué car l'UI n'a pas changé.

## Limites

Cette passe reconnaît des noms et formats courants ; elle n'est pas un scanner universel de secrets propriétaires, de données encodées ou de contenu sans affectation identifiable. Une clé nommée de façon arbitraire peut encore échapper aux motifs. Les tests ne qualifient aucun service d'entreprise ni aucune clé réelle. L'état G0 reste **10 PARTIAL / 2 NOT_IMPLEMENTED / 0 IMPLEMENTED** ; aucune parité globale avec les douze références n'est revendiquée.

L'archive cumulative R130 ne sera déclarée prête qu'après réussite des trois workflows au même SHA, contrôle des manifestes, présence des binaires Windows réellement générés et vérification de l'intégrité et du SHA-256 du ZIP téléchargé.
