# OpenRemote Studio V31.8 — R110 : consentement Zabbix lié à l'origine HTTPS

Auteur : **Abdelhalim Talbi**. Statut : correction P1 sur branche dédiée ; qualification Windows à confirmer par les workflows associés au commit exact.

## Constat R109

Le panneau Zabbix effaçait les données et invalidait les résultats asynchrones lors d'un changement d'origine, mais la case de consentement réseau restait cochée. Un clic sur « Actualiser » pouvait donc relire le jeton d'environnement et l'envoyer à la nouvelle origine sans nouvelle approbation dédiée à cette cible.

## Correction

Application/zabbix_alerts_qt.py traite désormais toute modification du champ d'origine comme une révocation de consentement :

- la case d'autorisation est décochée automatiquement ;
- la requête en attente reçoit le signal d'annulation coopérative ;
- les alertes précédentes sont effacées et les réponses d'une génération obsolète restent rejetées ;
- une actualisation reste hors ligne tant que l'opérateur n'a pas explicitement re-coché le consentement ;
- le fournisseur du jeton n'est jamais appelé par l'édition du champ ou par une actualisation sans consentement.

Les filtres locaux et la modification de la limite n'entraînent pas de nouvelle requête. Les garanties R109 restent inchangées : HTTPS/TLS strict, redirections refusées, appels problem.get/trigger.get uniquement, réponses bornées et erreurs neutres.

## Tests et preuve UI

- Application/tests/test_zabbix_consent_binding_r110.py : nouvelle approbation requise après changement d'origine, absence de seconde lecture du jeton, révocation pendant une requête et rejet du résultat tardif.
- Application/tests/capture_zabbix_consent_r110.py : capture de l'état réel de l'interface Qt après révocation automatique, avec origine .invalid, aucun jeton et aucune connexion réseau.
- Application/zabbix_alerts_qt.py : correction du raccordement de origin.textChanged vers _origin_changed.

Les tests utilisent un transport synthétique et ne prétendent pas qualifier un serveur Zabbix réel.

## Limite de révocation

Une requête HTTPS déjà entrée dans la pile réseau ne peut pas être garantie annulée au milieu d'une opération de lecture. Elle reste limitée par le timeout et son résultat ne peut plus être affiché après révocation. Le changement empêche les requêtes suivantes de réutiliser le consentement précédent ; il ne retire pas un jeton déjà transmis dans une requête en vol.

## État de couverture

Zabbix reste **PARTIAL** : le contrat API et le panneau existent, mais l'instance réelle, le rôle à privilèges minimaux et le comportement de production sont **UNVERIFIED**. La matrice reste **8 PARTIAL / 4 NOT_IMPLEMENTED / 0 IMPLEMENTED** sur les douze références. Aucune parité ni recette réelle Zabbix n'est revendiquée.
