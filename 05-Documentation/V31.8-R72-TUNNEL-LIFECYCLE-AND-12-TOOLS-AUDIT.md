### R72 — défaut P0 corrigé

`remote_tools.Tunnel.__init__` réserve le port TCP avant que le thread serveur démarre. L'ancien `close()` appelait toujours `socketserver.shutdown()`; selon la bibliothèque standard, cet appel attend que `serve_forever()` soit lancé. Une annulation entre construction et démarrage pouvait donc bloquer le worker, empêcher la libération du port et laisser l'UI dans un état incertain.

Correction : machine d'état protégée par verrou; fermeture avant démarrage sans `shutdown()`; fermeture répétée sans effet; démarrage après fermeture refusé; `localhost` borné à IPv4 loopback; `::1` via serveur IPv6; rejet de cibles contenant des caractères de contrôle. Aucun port public n'est autorisé.

**Preuve locale Linux :** `PYTHONPATH=Application python -m unittest discover -s Application/tests -p 'test_tunnel_lifecycle_r72.py' -v` : 5 tests PASS le 2026-10-23. Le test de forwarding utilise de vraies sockets TCP locales et `socketpair` pour simuler le canal SSH; **aucun serveur SSH réel, aucune session Windows, aucun client VNC, aucun NAS et aucune capture UI** ne sont impliqués.

**Gates CI demandés :** Windows native et cumulatif, sur le SHA exact de la PR; résultat à relever après exécution. Ne pas considérer une simple compilation comme recette OpenSSH/Qt.
