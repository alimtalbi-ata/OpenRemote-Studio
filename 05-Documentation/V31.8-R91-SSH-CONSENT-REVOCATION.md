# OpenRemote Studio V31.8 — R91 : retrait du consentement SSH et révocation active

**Auteur : Abdelhalim Talbi** · **24 octobre 2026** · **Priorité P0** · **Statut : branche draft, non fusionnée**

## Défaillance métier reproduite par analyse du code R90

Dans `Application/ssh_tunnel_qt.py`, retirer la coche d'autorisation après démarrage appelait `SSHConsentGuard.revoke()`, mais **ne fermait pas le tunnel**. La fermeture n'était déclenchée que par un changement de champ lorsque la case était encore cochée. Une modification programmatique de champ après une case déjà décochée pouvait donc laisser la connexion active.

L'interface Qt désactive normalement la case pendant la connexion, mais `QCheckBox.setChecked(False)` et `QLineEdit.setText()` restent utilisables par programmation. L'état `enabled` du widget n'est pas une barrière de sécurité.

## Correction

- `_revoke_live_tunnel()` demande la fermeture lorsque le contrôleur est `connecting` ou `active`.
- `_consent_toggled(False)` révoque le consentement **et** le tunnel actif, sans exiger une modification de formulaire.
- `_configuration_changed()` révoque également une connexion active lorsque la case est déjà décochée, y compris si son signal a été bloqué précédemment.
- Une édition lorsque la case est cochée la décoche : le signal `toggled` exécute une seule demande de fermeture. Les contrôleurs à usage unique et la barrière de drainage R88 restent inchangés.
- Aucun secret, chemin de clé privée ou nom d'hôte n'est inscrit dans les messages de statut. Host-key SSH fail-closed, bind loopback et absence de reconnexion automatique conservés.

## Qualification

`Application/tests/test_ssh_consent_revocation_qt_r91.py` contient **cinq tests** : retrait pendant connexion, retrait pendant activité, modification après décoche sans signal, retrait hors ligne sans trafic, édition avec une seule révocation.

**Qualification locale au moment de la création :** syntaxe Python PASS ; cinq tests Qt découverts mais **ignorés** faute de PySide6 dans l'environnement local. Aucune réussite Qt n'est revendiquée localement.

Les workflows `windows-native.yml` et `v318-openssh-live.yml` exécutent explicitement ces cinq tests sur leurs environnements Qt. Les trois workflows sont configurés pour cette branche R91. Vérifier leurs conclusions et le SHA exact avant de déclarer Windows/OpenSSH/ZIP qualifiés.

## Limites et sécurité

Ces tests utilisent un contrôleur synthétique et **ne simulent pas un blackhole WAN**. Ils qualifient la logique Qt de révocation, pas la durée de détection réseau. Les scénarios OpenSSH R90 existants restent dans la CI pour détecter les régressions. Aucune recette opérateur Windows physique, aucune production et aucune acceptation automatique de nouvelle clé d'hôte.
