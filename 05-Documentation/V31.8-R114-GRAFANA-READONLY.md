# V31.8-R114 — Grafana : découverte de dashboards en lecture seule

**Auteur : Abdelhalim Talbi**  
**Cycle : R114 — 25 octobre 2026**  
**État : implémentation sur branche dédiée ; qualification CI encore attendue au HEAD final.**

## Objectif

Réduire une lacune P1 de la matrice des 12 outils en intégrant la découverte de tableaux de bord Grafana dans l'espace Outils d'OpenRemote Studio. L'application ne clone pas le moteur de visualisation Grafana : elle propose une passerelle minimale vers sa API et ses tableaux de bord, avec consentement explicite.

## Implémentation

- `Application/grafana_readonly.py` : client optionnel, hors ligne par défaut, API limitée à `GET /api/search` avec `type=dash-db`, taille de réponse plafonnée à 1 Mio et au plus 100 tableaux.
- `Application/grafana_dashboard_qt.py` : panneau Qt asynchrone avec recherche facultative, annulation, tableau des résultats et ouverture d'un lien uniquement à la demande de l'opérateur.
- `Application/qt_app.py` : entrée « Tableaux Grafana (lecture seule) » dans le menu **Outils**.
- `Application/tests/test_grafana_readonly_r114.py` : 19 tests de contrat offline / transport synthétique.
- `Application/tests/test_grafana_dashboard_qt_r114.py` : 9 tests Qt, exécutés lorsque PySide6 est disponible.
- Le présent dossier et le diagramme SVG sont inclus dans la documentation versionnée.
- Le test d'archive cumulative doit inclure une capture Qt réelle du panneau hors ligne générée par Windows CI, distincte de toute preuve d'un accès réel à Grafana.

## Barrières de sécurité

1. L'origine acceptée est une racine HTTPS sans identifiant, mot de passe, chemin, query ou fragment ; la validation est faite avant de lire le jeton.
2. Le client utilise le magasin de confiance TLS standard et refuse les redirections. Le seul verbe HTTP exposé est GET et le seul endpoint est `/api/search`.
3. Le jeton Bearer est passé à l'appel, placé dans l'en-tête Authorization et n'est jamais incorporé à l'URL, au résultat, à un journal ou à un export. La variable d'environnement `OPENREMOTE_GRAFANA_TOKEN` n'est consultée par le panneau qu'après consentement.
4. Aucun accès réseau automatique, polling, écriture, import, stockage persistant ou export de secret n'est proposé.
5. Toute modification de l'origine ou de la recherche, annulation, dissimulation ou fermeture révoque le consentement et vide les lignes affichées. Les réponses tardives ne peuvent pas réactiver le panneau.
6. Les liens sont reconstruits depuis l'origine validée et un UID Grafana validé ; les URLs renvoyées par le serveur ou par un adaptateur injecté ne sont pas ouvertes.
7. Les champs de titre, dossier et tags sont validés et assainis avant affichage. Les erreurs réseau sont normalisées en codes stables ; aucun texte de l'exception du transport n'est exposé.

## Qualification

Les tests contractuels utilisent un transport mémoire/synthétique et un jeton factice. Les tests Qt utilisent des clients injectés, ne contactent aucun serveur, et doivent être exécutés dans les workflows Windows natif et cumulatif. Une capture produite par le panneau avec le consentement désactivé est une capture **réelle de l'interface en mode hors ligne**, pas une capture d'un dashboard Grafana en ligne.

Les statuts CI, l'archive Windows cumulative, les manifestes et leurs SHA-256 doivent être liés au commit exact R114 avant d'étiqueter le cycle comme qualifié. Cette note ne préjuge pas de ces résultats.

## Limites explicites

- **Pas de serveur Grafana réel, de jeton réel ni de rôle API de laboratoire qualifiés dans ce cycle.** Le fonctionnement API effectif, les permissions minimales du jeton et la compatibilité avec une instance d'entreprise restent UNVERIFIED.
- La recherche utilise une seule page bornée à 100 entrées ; la pagination n'est pas implémentée. Une réponse dépassant les limites provoque un refus plutôt qu'un résultat partiel.
- Seule une instance servie à la racine de l'origine HTTPS est prise en charge ; un déploiement sous un sous-chemin inverse (reverse-proxy path prefix) doit être ajouté et qualifié séparément.
- La connexion initiale (DNS, handshake TLS et lecture des en-têtes) utilise le timeout d'inactivité de `urllib` : il ne s'agit pas d'une deadline murale stricte sur toute la transaction, et des en-têtes envoyés lentement peuvent prolonger l'attente avant le retour de l'ouverture. Après les en-têtes, le corps est plafonné et le temps restant est appliqué au socket standard lorsqu'il est introspectable ; une lecture native déjà bloquée ne peut pas être interrompue de force de manière portable. La deadline du corps est vérifiée à chaque retour de lecture, y compris l'EOF final. La révocation côté UI empêche l'affichage d'un résultat tardif, mais ne garantit pas l'arrêt immédiat du worker réseau.
- Les tests d'interface offscreen ne remplacent pas une recette opérateur sur poste Windows physique. Aucun tableau de bord ou donnée en direct n'est inventé dans les tests.
- La signature des binaires, la connexion à un serveur Grafana réel et l'acceptation opérateur ne sont pas attestées par les tests simulés.
