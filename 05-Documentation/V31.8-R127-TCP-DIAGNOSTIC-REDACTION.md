# OpenRemote Studio V31.8 — R127 : expurger les erreurs du diagnostic TCP

**Auteur : Abdelhalim Talbi.** **Date : 26 octobre 2026.** Branche dédiée : `feature/v31.8-r127-tcp-diagnostic-redaction`, empilée sur R126. La PR reste en brouillon ; aucune fusion automatique vers `main`.

## Défaut confirmé dans le code

L'audit de `Application/qt_workers.py` a trouvé que `TcpJob.run()` interpolait directement l'exception réseau au signal Qt `finished`. Le résultat est affiché dans le journal ou dans le panneau de diagnostic de chemin. Les objets `OSError` issus du système ou d'un adaptateur peuvent transporter un nom de cible ou d'autres détails fournis par une couche intermédiaire. `Application/network_probe.py` n'affichait pas leur texte brut, mais ne renvoyait qu'un nom de classe d'exception, peu utile à l'opérateur.

## Correction

- Nouveau `Application/network_error_reporting.py` : conversion des catégories DNS, délai dépassé, refus, permissions, réseau inaccessible et interruption en messages constants, sans appel à `str(exc)` ou `repr(exc)`.
- `TcpJob` valide l'hôte et le port avant le moindre appel réseau. Une entrée invalide renvoie un résultat fixe sans réafficher la valeur reçue et sans ouvrir de socket. Les littéraux IPv6 sont affichés entre crochets.
- `TcpJob` transmet uniquement le résultat expurgé au signal Qt.
- `network_probe.probe()` réutilise la même taxonomie afin de ne pas exposer le texte brut ni le nom de classe de l'exception.

Le contrôle TCP reste un test explicite de port depuis le poste local. Il ne prouve ni l'authentification, ni la traversée d'un bastion, ni la santé applicative. Les tests unitaires n'exécutent pas de connexion vers une cible externe.

## Tests et gates

`Application/tests/test_network_error_reporting_r127.py` vérifie les catégories, les sentinelles confidentielles, une exception non stringifiable et l'intégration de `network_probe.probe()`. `Application/tests/test_tcp_error_redaction_r127.py` observe le vrai signal Qt `TcpJob.finished`, vérifie la non-divulgation du texte d'exception, refuse un hôte contenant des identifiants et contrôle le format IPv6.

Les gates Windows native et cumulative doivent exécuter l'intégration avec PySide6 présent, sans skip, puis compiler les sources. La gate OpenSSH/SFTP exécute les tests purs et les non-régressions de `network_probe`, tout en conservant ses scénarios existants contre le serveur OpenSSH jetable. L'existence d'un serveur OpenSSH dans cette lane n'est pas présentée comme une recette TCP d'entreprise.

## Audit des 12 outils et limites

La matrice G0 reste inchangée : MobaXterm, Royal TS, Devolutions Remote Desktop Manager, mRemoteNG, Termius, Windows Admin Center, Ansible, Zabbix, Grafana et NetBox restent `PARTIAL`; Wireshark et HashiCorp Vault restent `NOT_IMPLEMENTED`. Aucun cas d'usage n'est promu sur la base de ce correctif. Les qualifications E2E externes restent limitées, notamment pour les services d'entreprise et les rôles d'accès minimaux.

Cette correction couvre `TcpJob` et `network_probe.probe()`, pas tous les producteurs de diagnostics de l'application. Les autres messages d'erreur restent à auditer. Aucun changement UI n'est revendiqué et aucune capture R127 n'est fournie ; le SVG associé est conceptuel. Aucun secret de production, hôte métier ou déploiement distant n'est utilisé.
